# Expert loader on a real MoE checkpoint (2026-11-05)

TASK-08 acceptance run. `tfload` (ReleaseFast, `-Dcpu=native`) loads only the experts one engine process owns from allenai's OLMoE-1B-7B-0924-Instruct GGUF, through the TASK-03 io_uring O_DIRECT reader, and checks each expert's CRC32C against the file's `.tfsum` index.

| Item | Value |
|---|---|
| Model file | `olmoe-1b-7b-0924-instruct-q8_0.gguf` from [allenai/OLMoE-1B-7B-0924-Instruct-GGUF](https://huggingface.co/allenai/OLMoE-1B-7B-0924-Instruct-GGUF) (Apache-2.0), 7,359,943,136 bytes, SHA-256 `d089e8b1...8909c66` (matches Hugging Face's listing) |
| Model shape | 16 layers x 64 experts, d_model 2048, expert d_ff 1024; experts Q8_0 (6.68 MB per expert per layer, 6.85 GB of experts in all) |
| Reader | queue depth 16, 1 MiB requests, plans aligned to 4,096 bytes, gaps up to 64 KiB read through |
| Machine | `gx10-03`, same drive and kernel as [`gx10-03-2026-10-27.md`](gx10-03-2026-10-27.md); co-tenant vLLM resident, GPU 0%, load average about 0.3, 15 GB of memory available |

## Results

| Experts loaded | Bytes read | Spans | Read time | Read rate | CRC32C check |
|---|---|---|---|---|---|
| 0 to 31 (half) | 3.42 GB | 48 (one per stacked tensor) | 0.486 to 0.601 s | 5.69 to 7.05 GB/s (7.0 after the first two runs) | all 1,536 weights OK, 0.127 s |
| 32 to 63 (half) | 3.42 GB | 48 | 0.486 to 0.589 s | 5.82 to 7.05 GB/s | all OK, 0.13 s |
| 0 to 15, 48 to 63 (quarter) | 1.71 GB | 48 | 0.248 s | 6.90 GB/s | all OK, 0.064 s |

The steady rate, 7.0 GB/s, is 97% of the drive's 7.24 GB/s measured with `fio` on Oct 27. Building the `.tfsum` index (CRC32C of all 3,072 expert weights, 6.85 GB) took 1.65 s.

**Dequantized values** (desktop, WSL2, same file by SHA-256): 18 expert weights (layers 0 and 15; gate, up, down; experts 0, 17, 31) are bit-identical to llama.cpp's gguf-py dequantizer (`tools/ref/ref_quant.py --model`), max absolute difference 0.

The block formats the real file does not use are covered by fixtures in `tests/golden/`, also bit-identical: MXFP4 and NVFP4 GGUF blocks against gguf-py, and a ModelOpt NVFP4 safetensors checkpoint against PyTorch's `float8_e4m3fn` decoding. The unit tests and CI load subsets of both fixtures through the same code.

## Notes

- **Touch the region before timing.** The first runs, on a freshly mapped region, read at 0.66 to 3.78 GB/s, because the kernel found and zeroed pages during the I/O, with only 11 to 15 GB free next to the co-tenant. The engine maps its arenas at startup, so `tfload` now touches the region first (0.09 s for 3.42 GB) and times the read alone. A 6.85 GB run (all 64 experts) went above the 4 GB-per-process cap and pushed the machine into reclaim; it is not repeated.
- **No fixed buffer.** io_uring refuses to register a buffer over 1 GiB, so these reads pin pages per request. That costs little at 1 MiB per request, as the 7.0 GB/s shows. Splitting the region into 1 GiB registrations is a possible later change.
- **Checksums are a sidecar.** Neither GGUF nor safetensors stores checksums, so `tfload index` writes `MODEL.tfsum` (CRC32C per expert byte range) once; every load checks the experts it reads against it and refuses a file whose size differs. The whole file was checked once against Hugging Face's SHA-256 at download.
- **Metadata:** allenai's conversion predates `olmoe.expert_feed_forward_length`; the loader falls back to `olmoe.feed_forward_length`, as llama.cpp does for this all-MoE model.
