# Prefetch and cache misses in the live view (TASK-41, 2026-11-18)

The "One token" view in `web/live.html` now shows how each expert call found its expert when rank 0 streams experts from NVMe through its cache: already in memory, prefetched by a lookahead hint in time, prefetched but still loading, or missed (the token waits on the drive). It also shows each hint the lookahead router sends and each load from the drive that a hint brought in.

## What the engine sends

Two new fields in each step frame and one in the hello, all added to `tensorfold.live` v0, so older recordings still replay (`docs/telemetry-schema.md`):

- **`c`:** `layer, expert, status` for each of rank 0's cache calls in the step (1 resident, 2 hinted, 3 late, 4 missed). `ExpertCache.poll` already decided each call's status for its counters; it now also notes it in a per-step array of one byte per layer and expert, owned by the telemetry tap (`CacheTrace` in `src/telemetry.zig`).
- **`h`:** `for layer, expert, sent during layer` for each hint. The tap already wrapped `Moe.prefetch`; it now records each hint with the layer the forward pass is in when it is sent. A guess made inside layer L, before its experts run, is sent during L; the guesses from the embeddings are sent during layer 0.
- **`cache_ranks`** in the hello: the ranks that have a cache, so the page draws a drive there.

Nothing is noted unless a viewer or a recording is attached: the tap turns the cache's notes on only for steps it counts. When a step calls the same expert of a layer twice (prefill on the CPU), only the first call's status is kept; with `--gpu` or in decode each expert of a layer is called once per step.

**Unit tests** (`zig build test`, 116 on `gx10-02`; 98 plus 1 skipped natively on Windows):
- `expert_cache.zig`: over four rounds of a two-slot cache, the statuses noted add up to the change in each of the cache's counters, the pinned layer is always resident, and a round with the trace off notes nothing.
- `telemetry.zig`: without a viewer, hints still reach the engine but nothing is noted or published; with one, the frame carries the expected `c` and `h`, and the frame and hello are valid JSON.

## What the page shows

- **The drive:** a strip at the bottom of each machine with a cache, labeled "NVMe drive", with the token's counts beside it ("this token: 226 in memory, 11 prefetched, 70 late, 77 missed", shortened to fit).
- **Hints:** during the layer that sends them, a faint packet from the router toward each guessed expert (over the cable for another machine's expert).
- **Loads:** for each hint whose expert was then found prefetched or still loading, a dot travels from the drive to the expert along a faint track.
- **New expert states**, with a row in the key: prefetched and ready (green ring), loading from the drive (dashed ring), and missed (red ring). A picked expert that missed or was late waits on the drive, with its load drawn, before it works.

Checked in the Claude browser pane (Chromium) with both recordings below, in dark and light themes and at phone width (375 px). Every line of both recordings was accepted. The TASK-31 Qwen3.8 recording, which has none of the new fields, replays as before. `npm run build` passes its bundle check (0.168 MB initial load), with the new recording as a 2.3 MB file loaded when chosen.

## The recordings

Qwen3-30B-A3B (Q8_0, 48 layers of 128 experts) on `gx10-02` alone, its 6,144 experts (5 MB each) streamed from NVMe through a 3,000-slot cache (15.1 GB), cached experts on the GPU. The same scripted three-turn chat as the other replays (`tools/ref/record_chat.py --thinking --max-tokens 500`), once without lookahead and once with `--lookahead 1` (`2026-11-18/chat.sh`, build in `2026-11-18/versions.txt`).

TASK-41's plan was to rerun the TASK-31 Qwen3.8-Flash-Next chat. Its GGUF (163 GB) had been deleted from `gx10-02` to make room for GLM-5.3-Flash, which TASK-32's next window still needs, and only 97 GB are free. The user chose Qwen3-30B-A3B instead (Nov 18).

`2026-11-18/check_cache_frames.py` checks every step after the first: its statuses add up exactly to the change in the engine's own counters. All 1,182 and 1,128 steps match.

| | Without lookahead | With `--lookahead 1` |
|---|---|---|
| Steps | 1,183 | 1,129 |
| Expert calls | 463,328 | 442,317 |
| Already in memory | 95.8% | 95.0% |
| Prefetched in time | 0% | 1.2% |
| Prefetched, still loading | 0% | 1.9% |
| Missed | 4.2% | 2.0% |
| Turn 1: first token, decode | 3.77 s, 23.5 tokens/s | 3.76 s, 24.7 tokens/s |
| Turn 2: first token, decode | 1.83 s, 27.2 tokens/s | 1.62 s, 27.5 tokens/s |
| Turn 3: first token, decode | 1.58 s, 21.1 tokens/s | 1.07 s, 22.8 tokens/s |

- Lookahead halves the misses, but most of what it brings in is still loading when needed: with a horizon of one layer, a load has only the rest of one layer (about 0.8 ms in decode) to finish.
- It sent 551,503 hints. 72.5% named an expert already in memory, 23.9% one the layer then did not call (each token's guess holds 10 experts for its 8), and 2.4% brought an expert in from the drive (0.9% in time, 1.5% late). For 1.2% the expert was still missed, its hint having been dropped as stale or the slot reused before the call.
- The first turn's prefill starts with only layer 0's experts in memory, so nearly every call there misses.

**The two chats differ from turn 2 on.** Both start turn 2 the same and then diverge, so turn 3's prompt is 243 tokens without lookahead and 203 with it. Lookahead changes no result, so this was checked (`--context 1024 --generate 128 --compare`, repo tokens): with the cache on the GPU, two runs without lookahead give the same 128 tokens but logits up to 6.1e-5 apart, and one with lookahead up to 7.9e-4 apart; without the cache, two GPU runs are identical bit for bit. Which of a layer's experts are ready together decides how the GPU groups them, and so the order their outputs are added up, which moves the rounding with the load timing. The chat met a near-tie in turn 2. This predated TASK-41 and was fixed the same day (`bench/olmoe/2026-11-18-cache-determinism.md`); these recordings were made before the fix. Turns 1 and 2's prompts are the same in both runs, so their hit rates compare directly.
