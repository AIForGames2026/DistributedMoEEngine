# Keys in BF16, values in FP8 (TASK-27 follow-up, 2026-11-16)

`--kv-format bf16_fp8` stores keys as `bf16` and values as `fp8`, in the same row formats as those two (`src/kv_format.zig`). The first TASK-27 run ([`2026-11-16-kv-formats.md`](2026-11-16-kv-formats.md)) found that FP8 loses its accuracy in the keys. With only the values in FP8, every OLMoE prompt top-1 stayed the same.

How it works:

- A cache now has a row size for keys and one for values (`KvCache.row`), so each layer's keys and values take different amounts of memory.
- Each GPU attention kernel gets a fourth compiled variant that reads keys as bf16 and values as fp8. The f32, bf16 and fp8 kernels are unchanged.
- Saved prefixes (TASK-28) store each layer's keys and values at their own sizes.
- The NVMe tier (TASK-12) gives keys and values one tile size, the larger. That keeps its tile bookkeeping shared, and leaves part of each value tile unused.

Raw logs, the script that ran them, and versions are in [`2026-11-16-kv-bf16-fp8/`](2026-11-16-kv-bf16-fp8/).

Build:

- `gx10-02`: this change on commit `59e8a5a` (`v0.2.0-alpha-31-g59e8a5a-kv27b`), ReleaseFast, `-Dgpu=true -Drdma=true`.
- The reference build is commit `59e8a5a` itself.
- Machine: kernel 7.0.0-1019-nvidia, driver 580.178.04, Zig 0.17.0, nothing else running.

## Unchanged f32, saved prefixes, and the NVMe tier

- **f32 against the committed build** (`regress-*.log`):
  - At 32,640 tokens, all 128 generated tokens and their logits match bit for bit.
  - First token 49.4 s against 50.0 s; decode 15.23 against 15.53 tokens/s. The same binary's f32 runs in `long32` decoded at 15.51 and 15.47, so this is run-to-run variation.
- **Saved prefixes** (`prefix-*.log`, 16k prompts):
  - A full restore and a partial one (10,240 positions from a 12,000-position file) give exactly a cold run's tokens and logits.
  - The file is 1.22 GB at 16,384 positions (bf16 1.61 GB, fp8 0.83 GB).
  - A full restore takes 0.24 s, and the first token comes in 0.28 s instead of 18.5 s.
- **NVMe tier** (`tier-*.log`, 32,640 tokens, window 8,192):
  - The run with the middle on NVMe gives exactly the all-in-memory run's 32 tokens and logits.
  - Decode with the tier is 2.54 tokens/s, against 2.68 for bf16 and 3.75 for fp8. The tier moves value tiles at the size of key tiles, so it reads as much as bf16 does.
