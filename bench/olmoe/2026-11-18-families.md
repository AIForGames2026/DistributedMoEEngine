# Mixtral, DeepSeek V3 and gpt-oss (2026-11-18)

TASK-39. Three model families, each with something the engine lacked. llama.cpp's per-architecture code (`src/models/deepseek2.cpp`, `openai-moe.cpp`, `llama.cpp`, and its converter in `conversion/`) was read as the record of each GGUF's tensor names, shapes and converter transformations. No llama.cpp code was copied, so `THIRD_PARTY.md` is unchanged. The reference is transformers 4.57.1, in float32 on each GGUF's dequantized weights.

## The models

| Family | Real model checked | GGUF (source, size) | GGUF architecture |
|---|---|---|---|
| Mixtral | Mixtral-8x7B-Instruct-v0.1 | mradermacher, Q4_K_M, 28.5 GB | `llama` with experts |
| DeepSeek V3 and Kimi K2 | Moonlight-16B-A3B-Instruct (Moonshot's, `DeepseekV3ForCausalLM`) | gabriellarson, Q4_K_M, 10.5 GB | `deepseek2` |
| gpt-oss | gpt-oss-20b | ggml-org, MXFP4, 12.1 GB | `gpt-oss` |

- **DeepSeek V3 itself:** at 671B parameters it fits on no machine we have. Moonlight has the same architecture: MLA with decoupled rope, sigmoid routing with a choice bias, shared experts and a dense first layer. Its routing has a single group, so group-limited routing is checked by the tiny model only.
- **Mixtral:** TheBloke's GGUF (December 2023) stores each expert as a separate tensor, a layout from before llama.cpp merged them. mradermacher's 2025 conversion of the same model was used instead.

## What was built

- **Mixtral** (`olmoe.zig`, arch `mixtral`): a GGUF "llama" with experts. It runs on the existing layer loop, with no QK norm and rope on adjacent pairs. llama.cpp's converter permutes each head's query and key rows for that rope, and the reference undoes it.
- **DeepSeek V3** (`src/deepseek.zig`, its own step like GLM-5.3-Flash's):
  - **Attention:** MLA with an optional query rank. The cache keeps one row per position: the normalized latent, then the rotated key part every head shares. Each head's key projection is folded into its query, and its value projection is applied after attention, as in llama.cpp.
  - **Routing:** sigmoid scores. The choice adds a bias and stays within the best groups of experts, each group scored by its two best experts. Experts outside those groups score 0, as in transformers, not minus infinity as in llama.cpp. The chosen scores are renormalized and scaled.
  - **Other blocks:** dense leading layers and shared experts (GLM's MLP, now shared), and YaRN with DeepSeek's attention scale.
- **gpt-oss** (`src/gptoss.zig` with the existing layer loop):
  - **Attention:** biases on the attention projections, a learned sink per head in every softmax, and a 128-position sliding window on every other layer from the first.
  - **Rope:** YaRN without whole-dimension ramp ends (transformers' `truncate: false`, which the GGUF does not record).
  - **Router and experts:** a router bias, and expert biases with gpt-oss's clamped SwiGLU.
- **Expert biases:**
  - The loader makes each GGUF expert's bias part 1 of its weight, so read plans and `.tfsum` checksums cover it.
  - `Expert` adds the biases on every CPU path.
  - The GPU's expert kernels refuse biased experts, which then run on the CPU and are reported ("the GPU's expert kernels add no biases and use no gpt-oss SwiGLU").
  - The expert cache (`--cache`) refuses gpt-oss, since its slots hold no biases.
- **Kimi's tokenizer** (`kimi-k2` pre-tokenizer, which Moonlight uses):
  - **Pattern:** gpt-4o's with Han split out, following Moonshot's tiktoken pattern, with merges ignored.
  - **Unicode:** `gen_unicode.py` adds a Han table from the `regex` package, since `unicodedata` has no scripts.
  - **Check:** `check_tokenizer.py` takes a directory, for tokenizers with no tokenizer.json, and runs Moonshot's tokenizer code (`trust_remote_code`, tiktoken).
- **gpt-oss's replies in the server:** its harmony markers now pick the channel. The analysis channel goes to `reasoning_content` and the final channel to `content`, where before the channel names were printed into the content.
- **References:** `tools/ref/ref_mixtral.py`, `ref_deepseek.py` and `ref_gptoss.py` load each GGUF into transformers' own model, with experts dequantized when a token picks them. Each also writes a tiny random model (`--tiny`). gpt-oss's lazy experts are transformers' own CPU expert loop.
- **Fixes found on the way:**
  - `olmoe` read only part 0 of each expert, so a gpt-oss expert's bias was never loaded and failed its checksum.
  - `tfload`'s summary described three gate weights rather than one expert's three projections, and Moonlight's dense first layer rather than its experts.

## Checks on `gx10-02`

**Tiny models** (in `zig build test`, and through `olmoe` with `--payload f32`): each matches transformers on logits (within 4.4e-6), hidden states, every expert choice, and 16 generated tokens, in one process and split over three processes on the GPU. The tiny models test what the real ones do not:
- Mixtral's: grouped KV heads and a head size unlike d_model over heads.
- DeepSeek's: a query rank, four expert groups of which two are used, a choice bias, a dense first layer, and YaRN.
- gpt-oss's: a 4-position window that the 20-token prompt exceeds, sinks, biases, MXFP4 experts, and YaRN.

**Real models** against transformers (3 golden prompts, then 32 greedy tokens each), `--gpu` and CPU in one process, and split over three processes on the GPU with f32 activations. Logs are in `2026-11-18-families/logs/`.

| Model | Logits, worst | Expert choices same | Top-1 | Generated tokens same | Decode |
|---|---|---|---|---|---|
| Mixtral-8x7B (one process, GPU) | 1.57e-4 | 3,008 of 3,008 | 47 of 47 | 96 of 96 | 14.5 to 15.4 tokens/s |
| Moonlight-16B (one process, GPU) | 6.09e-4 | 6,084 of 6,084 | 39 of 39 | 96 of 96 | 26 to 28 tokens/s |
| gpt-oss-20b (one process, GPU) | 1.26e-4 | 3,552 of 3,552 | 37 of 37 | 96 of 96 | 4.9 to 5.2 tokens/s (experts on the CPU) |

- **CPU and split:** the CPU runs and the three-process splits gave the same counts, with logits within the same bounds.
- **Near-ties:** Moonlight's smallest gap between a chosen expert and the next is 6.8e-6, and still no choice differs.
- **The split's payload:** with its default fp8 activations, gpt-oss's split misses the bar: logits up to 1.04 off and 98.3% to 99.0% of expert choices the same. Its hidden states run into the hundreds, so fp8's rounding is too coarse to hold transformers' outputs (`gptoss-shm3-gpu-fp8.log`). The checks above use `--payload f32`, as TASK-32's did.

**Tokenizers** (`check_tokenizer.py`, 5,038 texts each, from the GGUF):
- **Moonlight:** every text matches Moonshot's tokenizer, 154,751 tokens.
- **gpt-oss:** every text matches its tokenizer.json, run again after the shared word matcher changed.
- **Mixtral (mradermacher's GGUF):** 117 of 5,038 match, because the file says `add_space_prefix = false`. Mixtral's own tokenizer puts `▁` before the first word, and so does TASK-37's conversion of the same tokenizer, which matches on every text. The engine follows the GGUF, as llama.cpp does, so with this file a prompt's first piece differs ("[" for "▁[") and a reply keeps its leading space. The golden checks above feed Hugging Face's own ids and are not affected.

**Chat:**
- **Templates:** the GGUF's own template renders as transformers does on all 140 prompts for each model (`check_chat.py --gguf-template`). Mixtral's template refused the same 7 conversations, and token ids are identical where a tokenizer.json exists (Mixtral 133 of 133, gpt-oss 140 of 140).
- **Through the server** (`--gpu --serve`), each answered "What is the capital of France?" correctly:
  - Mixtral at 14.7 tokens/s.
  - Moonlight at 30.8 tokens/s.
  - gpt-oss at 5.4 tokens/s, with its reasoning in `reasoning_content`.

**Unit tests:** 133 of 133 on `gx10-02`, and 115 plus 1 skipped on Windows.

## Not done

- **On the CPU only:**
  - gpt-oss's experts: the GPU kernels add no biases and use no gpt-oss SwiGLU.
  - gpt-oss's attention: the GPU kernel has no sinks or window.
  - DeepSeek's MLA attention, as GLM's.
- **Expert cache:** gpt-oss does not run with `--cache`.
- **Lookahead:** DeepSeek's step does not take part, as GLM's does not, and gpt-oss's guesses leave out the router bias.
- **Not covered:**
  - DeepSeek V2's softmax router, and GGUFs with an unsplit `attn_kv_b`, are refused.
  - The full DeepSeek V3 and Kimi K2 weights were not run.
  - Tool calls in gpt-oss's harmony format stay out, as in TASK-38.
