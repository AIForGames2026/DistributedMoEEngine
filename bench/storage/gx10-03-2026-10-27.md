# Expert reader vs fio: gx10-03 (2026-10-27)

TASK-03 acceptance run for the io_uring O_DIRECT reader ([`csrc/io/uring_reader.c`](../../csrc/io/uring_reader.c)), using [`tools/bench/uring_bench.c`](../../tools/bench/uring_bench.c) on a 1 GiB pattern file. The file was deleted after the run.

| Item | Value |
|---|---|
| Drive | ESL01TBTLCZ-27J2-TYN, firmware ERFM12.0, PCIe Gen 4 x4 |
| Kernel / filesystem | Linux 7.0.0-1019-nvidia (aarch64), ext4, scheduler mq-deadline |
| DIO alignment (`statx`) | memory 4 B, offset 512 B |
| Registration | fixed buffer and fixed file both granted (`RLIMIT_MEMLOCK` unlimited) |
| Co-tenant load | vLLM resident, GPU 0%, load average about 0.1, 1 GB of memory free |

## Result: the reader matches the drive's ceiling

| Run (256 KiB, QD 64, O_DIRECT) | GB/s |
|---|---|
| `fio` 3.43, io_uring, fixed buffers + registered files (3 runs) | 7.26, 7.21, 7.26 |
| `fio` 3.43, io_uring, plain | 7.16 |
| **TensorFold reader** (3 runs) | **7.24, 7.26, 7.27** |

- About **100% of the `fio` baseline** (acceptance: at least 90%).
- `--verify` checked all 134 million 8-byte words: 0 mismatches.
- Page cache delta during every run: **+0 MiB** (`Cached` in `/proc/meminfo`).
- SQPOLL on or off makes no measurable difference at this rate (7.24 vs 7.25 GB/s).

## Block size and queue depth sweep (SQPOLL on)

| Block | QD 16 | QD 32 | QD 64 | QD 128 |
|---|---|---|---|---|
| 128 KiB | 6.05 GB/s, p50 332 us | 7.22, 567 us | 7.24, 1,139 us | 7.07, 2,286 us |
| 256 KiB | **7.22, 569 us** | 7.21, 1,139 us | 7.22, 2,285 us | 7.24, 4,577 us |
| 512 KiB | 7.28, 1,138 us | 7.22, 2,283 us | 7.24, 4,575 us | 7.17, 8,465 us |
| 1 MiB | 7.25, 2,284 us | 7.23, 4,579 us | 7.20, 8,905 us | 7.18, 9,606 us |

The drive saturates at about 7.2 GB/s once about 4 MiB is in flight. Beyond that, a deeper queue only adds latency: per-request latency is the queue's bytes in flight divided by bandwidth. **Engine default: 256 KiB x QD 16** (full bandwidth, p50 0.57 ms, p99 under 1 ms). One OLMoE-1B-7B expert in MXFP4 (about 3.5 MB) then loads in about 0.5 ms; a DeepSeek-V3-class expert (about 22 MB) in about 3 ms.

## WSL2 desktop (for reference)

256 KiB, QD 64, 32 MiB window: 6.24 GB/s, verify ok, page cache +0 MiB. WSL2's disk is a virtual disk file, so this is not a measurement of the desktop's drive.

## Implications

- **Risk R3 (NVMe streaming too slow) is retired for single-drive reads**: the engine gets the full drive bandwidth with fixed buffers into page-aligned memory.
- The remaining question for TASK-12 / TASK-15 is whether 7.2 GB/s holds while GPU kernels use LPDDR5X bandwidth at the same time.
