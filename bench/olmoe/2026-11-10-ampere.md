# OLMoE-1B-7B on an Ampere GPU (2026-11-10)

TASK-26 acceptance run. Classroom desktops mostly have RTX 3070-class GPUs (Ampere, compute capability 8.6), so `build.zig` now also compiles the CUDA kernel for `sm_86`. The kernel itself did not change. This run tests that build on the owner's laptop, whose RTX 3060 Laptop GPU is the same architecture with less memory (6 GB, against the 3070's 8 GB).

## Setup

The same run as [`2026-11-05.md`](2026-11-05.md): three golden prompts compared with transformers' `OlmoeForCausalLM` on the same Q8_0 weights, F32 payload, `--gpu` on both sides. The model is split across two machines, because 6 GB cannot hold all 7.4 GB:

| Rank | Machine | GPU | Holds |
|---|---|---|---|
| 0 (router) | Laptop, WSL2 Ubuntu | RTX 3060 Laptop GPU, compute 8.6, 6 GB, driver 610.47 | Attention, router, LM head, experts 0 to 31: 3.94 GB on the GPU |
| 1 (expert) | Desktop, WSL2 Ubuntu 24.04 | RTX 5070 Ti, compute 12.0, 16 GB | Experts 32 to 63: 3.42 GB on the GPU |

The link is TCP over Tailscale, which connects these two directly (about 2 to 4 ms round trip, no relay). WSL2 cannot accept connections from outside the machine, so a small forwarder on the desktop's Windows side relayed the laptop's connection in; it accepted only the laptop's Tailscale address. The binary is one ReleaseFast build with `-Dgpu=true`, whose fatbin holds `sm_86`, `sm_120`, and `sm_121` code plus `compute_120` PTX (listed with `cuobjdump`).

## Results

With `TF_GPU_CHECK=1`, which recomputes every GPU matmul on the CPU and logs any output more than 1e-3 away:

| Prompt | Logits max err (target 1e-2) | Top-1 | Hidden max err | Experts chosen identical |
|---|---|---|---|---|
| 5 tokens | 2.10e-5 | 5/5 | 2.67e-4 | 640/640 |
| 21 tokens | 3.53e-5 | 21/21 | 3.13e-4 | 2,688/2,688 |
| 17 tokens | 3.43e-5 | 17/17 | 3.13e-4 | 2,176/2,176 |

**PASS.** No GPU result differed from the CPU by more than 1e-3; the check logs nothing unless one does. The 3060 sent 2,627 expert calls to the desktop, the same count as every earlier run of these prompts, and both processes exited cleanly. The 2.10e-5 and 3.43e-5 differ slightly from the 5070 Ti's one-process numbers (2.48e-5 and 3.77e-5) because the GPUs round float sums in a different order; both are far inside the target.

The 5070 Ti, rebuilt with `sm_86` added, still passes on its own with the same check and the same timings as before (0.53 s for the 21-token prompt), so the extra target changed nothing for Blackwell.

## Timing

A second run without the check, same setup (PASS again, worst logits error 4.01e-5):

| Run | Time per prompt (5 / 21 / 17 tokens) |
|---|---|
| **Laptop RTX 3060 + desktop 5070 Ti, Tailscale TCP (this run)** | 0.61 / 2.34 / 2.10 s |
| Desktop 5070 Ti, one process ([`2026-11-05.md`](2026-11-05.md)) | 0.13 / 0.50 / 0.41 s |
| `gx10-03` GB10, two processes over RDMA ([`2026-11-05.md`](2026-11-05.md)) | 0.20 / 0.81 / 0.67 s |
| Desktop and `gx10-03`, CPU, direct TCP ([`../transport/2026-11-05-direct-path.md`](../transport/2026-11-05-direct-path.md)) | 2.27 / 5.06 / 3.94 s |

The split is about 4.5 times slower than the 5070 Ti alone. We did not time the GPU's share separately, but the link alone accounts for a large part of it. `dispatch` between the same two machines (the laptop's native Windows `dispatch.exe` connecting to the desktop's over Tailscale, no WSL2 or forwarder) measured:

| `dispatch router`, laptop to desktop, 64 slots | Result |
|---|---|
| `--latency`, one way, p50 (two runs of 1,024 round trips) | 1,672 and 1,701 µs (min 1,198 µs, p99 3,725 to 4,769 µs) |
| `--packets 4096` | 2.80 s, 682 µs per token, 0.18 Gb/s both directions |
| `--oneway`, 16,384 packets | 0.18 Gb/s |

At 0.18 Gb/s, the run's 40 MB each way takes about 2 s of the 5 s that the three prompts took, before counting each layer's round trip. The laptop is on Wi-Fi, and Tailscale encrypts every packet. Loading the laptop's half onto its GPU took 1.1 to 1.8 s.

The inspector's "Desktop + laptop (RTX 3060), Tailscale" cluster uses the 1,686 µs p50 as its link latency.

## What this means for classroom machines

- **One Ampere card holds half the model.** 3.94 GB used 6 GB comfortably; a 3070's 8 GB leaves more room, but not enough for the whole 7.4 GB model next to the CUDA context and the desktop.
- **Ampere stays on the Q8_0 kernel.** It has no FP4 or FP8 tensor cores, so the planned NVFP4 kernels remain Blackwell-only.
- **The engine needs Linux.** On Windows that means WSL2 with Ubuntu 24.04 (the binary needs glibc 2.36 or newer) and `liburing2`; the NVIDIA Windows driver provides the GPU inside WSL2.
