## Answers to the TASK-05 questions

1. **Compute capability:** 12.1 on `gx10-03`, 12.0 on the desktop. Kernels target `sm_121a` and `sm_120a`; ptxas in CUDA 13.0 also offers the `sm_120f` / `sm_121f` family targets.
2. **tcgen05 / Tensor Memory: not available.** [`tools/probe/tcgen05.ptx`](../../tools/probe/tcgen05.ptx) (`tcgen05.alloc` + `relinquish_alloc_permit`) assembles for the `sm_100a` control but fails on `sm_120a` and `sm_121a` with "Instruction 'tcgen05.alloc' not supported." The FP4 GEMM (TASK-10) must use the consumer Blackwell path (warp-level block-scaled `mma.sync` with shared memory), not TMEM, and must fit tiles in the 99 KiB shared memory limit.
3. **ConnectX-7 and loopback:** answered on Oct 26: all four ports `ACTIVE` at 200 Gb/s, `ib_write_lat` runs in loopback.
4. **Hardware Decompression Engine: not available.** `CU_DEVICE_ATTRIBUTE_MEM_DECOMPRESS_ALGORITHM_MASK = 0` (no Deflate, Snappy, or LZ4) and `MEM_DECOMPRESS_MAXIMUM_LENGTH = 0`. The driver does accept an allocation with `CU_MEM_CREATE_USAGE_HW_DECOMPRESS` and reports that pointer as decompress-capable, but with no supported algorithms there is nothing to run on it. TASK-13 (compressed streaming) can only use software decompression (nvCOMP on the SMs or the CPU), and stays `could`.
5. **Bandwidth and free memory:** NVMe `ESL01TBTLCZ-27J2-TYN` (firmware ERFM12.0) links at 16 GT/s x4 (Gen 4), its maximum; ext4 root. About 11 GB of system memory is available (Oct 26 and again today), 1.9 GB of it as seen by CUDA. The memory and NVMe bandwidth runs (STREAM-style and `fio`) wait until the co-tenant is idle, and the `fio` baseline lands with TASK-03.

## New constraint: no GPUDirect RDMA

`CU_DEVICE_ATTRIBUTE_GPU_DIRECT_RDMA_SUPPORTED = 0`. The NIC cannot register `cudaMalloc` memory. On GB10 this costs nothing, because the CPU and GPU share the same LPDDR5X and the GPU can read pageable host memory: the engine registers host memory (the `Arena` mappings) with `ibv_reg_mr`, and kernels read and write the same pages. TASK-07 must not depend on `nvidia-peermem` or dma-buf export of device allocations.

## Co-tenant load

vLLM resident, GPU utilization 0%, about 2 GB of system memory free, swap in use.
