# Chat replay: Qwen3.8-Flash-Next on one DGX Spark (TASK-31, 2026-11-17)

This is a recording for the public page, of Qwen3.8-Flash-Next (Q8_0, 163 GB) on `gx10-02` alone. It is the same scripted three-turn chat as the other replays (`tools/ref/record_chat.py`): temperature 0, reasoning on, up to 500 tokens per reply.

Setup:

- **Command:** `olmoe local MODEL --gpu --cache 12000 --max-step 2048 --serve 127.0.0.1:8093 --ctx 8192 --record FILE`, using engine build `v0.2.0-alpha-42-g1b78bb4-q38k`.
- **Memory:** the non-expert weights (34.3 GB, including the 28.8 GB n-gram table) stay in memory. The 24,576 experts (128 GB) stream from NVMe through a 12,000-slot cache (63 GB), and cached experts run on the GPU.
- **Chat format:** `qwen38`, with the template's default `reasoning_effort` (xhigh). The generation prompt opens the `<think>` block, so each reply starts on the reasoning channel.
- **Files:**
  - `2026-11-17/chat.sh` is the script.
  - `chat-qwen38-one-spark.jsonl.gz` is the recording.
  - `chat-qwen38-one-spark.log` is the server's log.
  - `chat-qwen38-one-spark.txt` is the client's transcript, which shows the first 300 characters of each reply.

**The recording:**

- **Steps:** 469 in all (three prefills and 466 decode steps), none dropped.
- **Expert calls:** 469,440, matching the engine's own count.
- **The expert cache over the whole chat:**
  - 87.6% of calls already loaded;
  - 2.7% hinted but still loading;
  - 9.7% missed;
  - 22,880 loads.

All three replies finished on their own, inside the 500-token limit.

**Prefill is short, but its first token is slow.**

- A prompt of a few hundred tokens touches many experts that the cache does not hold yet, and each miss is a 2.5 MB read from NVMe.
- The first turn started with only layer 0's experts loaded.

**The server reused no prompt tokens across turns:** each turn's log line reads "0 reused".

- A Gated DeltaNet state cannot step back, and the last prompt position always runs again for its logits. So `KvCache.truncate` starts a hybrid model's session over, as for Qwen3.6 (TASK-29).
- Each turn therefore prefills the whole conversation.

## Speed against the other one-Spark replay

| Recording | Weights | Experts per token | First token | Decode |
|---|---|---|---|---|
| Qwen3-30B-A3B (`2026-11-15/chat-qwen3-one-spark`) | Q8_0, all in memory | 8 of 128 | 0.16 to 0.39 s | 36.5 to 37.4 tokens/s |
| Qwen3.8-Flash-Next (this one) | Q8_0, 163 GB, experts streamed from NVMe | 10 of 512, plus a shared expert | 6.8 to 11.1 s | 7.0 to 8.4 tokens/s |

**This model does not fit in `gx10-02`'s 121 GB.** It decodes at about a fifth of the in-memory model's speed. Its first tokens take 17 to 70 times as long:

- it reuses no prefix;
- its prompts touch experts the cache has to load.
